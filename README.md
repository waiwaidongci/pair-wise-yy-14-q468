# hxyfront-62013 榫卯勘测批次封样与替代构件放行台

古建筑木结构榫卯测绘台：在原「榫卯构件测绘」基础上扩展为**勘测批次封样与替代构件放行台**。
测绘员按建筑管理封样批次、开工锁定、缺项补录、替代件放行与补测重算；数据本地持久化，刷新后构件清单、关系图与批次状态保持一致。

## 业务规则

1. **封样唯一**：每栋建筑只保留一个封样批次，重复发起沿用首次批次，不新建。
2. **开工锁定**：开工即锁定木种、构件编号、截面；缺含水率或病害记录的构件只能补录，不能改录。
3. **替代件放行**：仅贯穿裂缝可申请替代件；木种、截面、榫型必须一致且未被其他批次占用，否则整单退回且不留占用。放行复核时再次比对，冲突同样整单退回。
4. **补测重算**：发起补测即冻结原批的关系边与修缮建议（旧版本只读）；换人两次确认（新测绘员不得与原批同一人）后按新值重算并追加新版本，改新值会使确认回到第一步。
5. **刷新一致**：全部状态写入 localStorage，刷新后清单、关系图、批次状态一致。

## 三个业务文件

| 文件 | 职责 |
| --- | --- |
| `src/business/componentLedger.ts` | 构件台账：建筑/构件/病害/备用构件类型、初始数据、台账查询（贯穿裂缝判定、木种截面榫型比对等） |
| `src/business/batchRules.ts` | 批次规则：封样/开工/补录/替代件/补测全部纯函数规则，版本快照、关系边与修缮建议派生 |
| `src/business/pageState.ts` | 页面状态：reducer 单一数据源、localStorage 持久化、演示种子、页面选择状态 |

UI 组件位于 `src/components/`（批次台、构件台账、补测工单、放行台、关系视图、侧边栏）。
